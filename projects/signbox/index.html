what it is

Signbox signs ipa files. you upload an app, pick a certificate, and it hands back a signed ipa with a direct install link. no ads, no account, no waiting in a queue. the tagline on the site says it: free ipa signing, no ads, no bs.

the story

  • i got tired of signing ipas the slow way. the services out there either cost money, fill the screen with ads, or make you wait in a queue. so i made a tool that does it on my own machine in one request.
  • it's a small express server. multer takes the upload, capped at 200mb. then the server opens the ipa with adm-zip, finds the app's Info.plist inside, and reads the bundle id, name, and version with plutil.
  • certs live in folders. each cert is a directory with a .p12 key, a .mobileprovision profile, and a password file. the server reads the provisioning profile with security cms -D to get the app id it's allowed to sign, so the bundle id gets rewritten to match the cert instead of guessing.
  • zsign does the actual signing. key, password, provisioning profile, bundle id, output. one command, no codesign ceremony.
  • the signed file goes to catbox. so the result is a plain https link you can send to anyone to install. no file hosting infra to babysit.

what happens when you sign

# upload an ipa (max 200mb)
POST /api/sign multipart: ipa + cert name

# server reads the app info out of the archive
unzip → Payload/*.app/Info.plist → plutil → bundle id, name, version

# re-sign with zsign, bundle id from the provisioning profile
zsign -k cert.p12 -p <password> -m profile.mobileprovision -b <app-id> -o signed.ipa input.ipa

# signed file → catbox for a direct install link
curl catbox.moe → https://files.catbox.moe/xxx.ipa

the apps list is tracked in a small json db, and there's a delete endpoint to clear it out when you're done.
