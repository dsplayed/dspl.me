Mage

what it is

Mage is a link-in-bio app. you get a username page where you put your links, socials, and whatever else, and it's supposed to look like you instead of a generic card grid.

the story

  • i wanted a link-in-bio that didn't look like every other one. most of them are templates with ads. so i built mine.
  • next.js and firebase. i wanted auth and a database without running my own server. email signup, a verify-email step, and firestore rules so nobody touches anyone else's profile.
  • the dashboard runs everything. links, badges, customization, settings, and a host mode, all behind auth. there's also explore and a leaderboard so profiles can actually be found instead of sitting in the dark.
  • uploads were the annoying part. firestore isn't for files, so i made a cloudflare worker that checks a short-lived upload token against firestore, streams the file into r2, and serves it back from the r2 domain. tokens expire after five minutes so they can't be replayed.
  • there's a sharex integration so screenshots go straight to your profile. that part is just convenience.

how the upload flow works

the worker does the file work instead of firebase, because storing files in a document database is a bad time:

# app asks worker for an upload token
POST /upload/token (firebase token checked)

# worker verifies against firestore, mints a token
200 { token, expiresIn: 300s }

# app PUTs the file to the worker with the token
PUT /upload Authorization: token (max 50mb)

# worker streams it into r2, returns the url
200 { url: "https://mage-r2.dsplay.workers.dev/..." }

the token dies after five minutes, so you can't steal one and use it later. the file lives in r2 and gets served straight from the worker domain, no firebase in the middle.
